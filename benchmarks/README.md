# Isolated black-box baseline

Do not install the baseline into the project environment. The production package
and dev lock never depend on it. `isolated/capture.py` is excluded from sdist and
wheel. The script refuses other baseline versions, verifies the corpus digest,
forces offline flags, disables telemetry and denies Python socket connections.
It neither downloads weights nor reads implementation source.

```sh
/absolute/external-baseline/bin/python -I benchmarks/isolated/capture.py \
  --model-dir /absolute/existing-model \
  --corpus benchmarks/corpus.seed-v2.json \
  --expected-corpus-sha256 35255104070be2c1fca922a042e9ef50124f887eb260026f0c5d0237a52d5980 \
  --out /absolute/new-observation-directory
```

Output directories must not already exist; files use exclusive creation.
Golden output must never be regenerated by the candidate under test. Observed
tokens/masks and vectors are in `observations/local-20260905`, with SHA-256s in
its environment manifest and `inputs.sha256.json`. Only synthetic corpus data is
captured. An OS sandbox offline proof, full baseline lock and independent review
are still required.

The first seed assumed one token per repeated word and was rejected by the
collector because the tokenizer adds a special token. `seed-2` explicitly uses
N-1 repeated tokens plus the observed suffix. The rejected seed remains available
for provenance. No successful golden output was overwritten.

Latency values in `vectors.json` are single diagnostic observations. They include
tokenization/forward/materialization/projection and have no separate warmup,
confidence intervals, thermal/power controls or cold sample population. They
must not be reported as performance acceptance results. A future benchmark suite
must cover direct and UDS, batch 1/4/16/32, token buckets 32/128/512, 30 cold and
100 warm samples, concurrency and a 30–60 minute soak on both required hosts.
